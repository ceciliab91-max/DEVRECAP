Parte 3 · API

Express e Prisma: query e API REST dello store

Interrogare lo schema con Prisma Client — dalle query base ai filtri per relazione, alle transazioni — e costruirci sopra l'API REST completa dello store con Express.

Capitolo 1

Il modello mentale delle query

Ogni query Prisma ha la stessa forma: client.<model>.<operazione>({ opzioni }) e ritorna una Promise. Cambiano il model e l'operazione, non la forma.

Lavoriamo sullo schema completo costruito nella dispensa precedente, Prisma: tipi, annotazioni e relazioni: nove model, con Category, Product, Tag, Order, User e Profile collegati da relazioni 1:1, 1:N e M:N esplicite.

Le operazioni si dividono in due famiglie, a seconda che restituiscano una riga o molte:

Famiglia Operazioni
Una riga findUnique, findFirst, create, update, upsert, delete
Molte righe findMany, createMany, updateMany, deleteMany, count, aggregate, groupBy

Tre famiglie di opzioni coprono quasi tutto: where decide quali righe, orderBy/take/skip decidono ordine e quantità, include/select decidono quali campi e relazioni tornano indietro. 

const economici = await client.product.findMany({
  where: { inStock: true },       // quali righe
  orderBy: { price: "asc" },      // ordine
  take: 5,                        // quantità
  include: { category: true }     // relazioni
});

Capitolo 2

Leggere una riga e leggere liste

findUnique accetta solo campi @id o @unique; findFirst accetta un filtro qualsiasi e usa orderBy per decidere chi è "il primo". 

// findUnique: SOLO per @id o campi @unique.
const p1 = await client.product.findUnique({ where: { id: 1 } });
const c1 = await client.category.findUnique({ where: { name: "Periferiche" } });

// findUniqueOrThrow: se non trova lancia P2025 (lo converte il middleware in 404).
const p2 = await client.product.findUniqueOrThrow({ where: { id: 1 } });

// findFirst: il primo che matcha un filtro qualsiasi (orderBy dice "primo" in che senso).
const p3 = await client.product.findFirst({
  where: { inStock: true },
  orderBy: { price: "asc" }        // il più economico disponibile
});

Per le liste si aggiungono ordinamento multiplo, skip/take per la paginazione e count per il totale, separato dalla pagina di dati:

const page = await client.product.findMany({
  where: { inStock: true },
  orderBy: [{ price: "desc" }, { name: "asc" }],   // ordinamento multiplo
  skip: 0,
  take: 10
});

const total = await client.product.count({ where: { inStock: true } });

Capitolo 3

I filtri

Più chiavi allo stesso livello di where sono in AND implicito; per un OR serve l'operatore esplicito OR.

await client.product.findMany({
  where: {
    name: { contains: "mouse" },           // LIKE '%mouse%' (MySQL è già case-insensitive)
    price: { gte: "20.00", lte: "100.00" }, // range: Decimal come STRINGA
    categoryId: { in: [1, 2] },
    description: { not: null },            // chi HA la descrizione
    inStock: { not: false },

    // Più chiave alla radice = AND implicito. Per OR:
    OR: [{ name: { startsWith: "Monitor" } }, { categoryId: 2 }]
  }
});

Su MySQL non esiste mode: "insensitive" (solo PostgreSQL/MongoDB): non serve, la collation utf8mb4_unicode_ci delle tabelle Prisma è già case-insensitive.

Capitolo 4

Scrivere

Le operazioni di scrittura su una riga singola sono quattro, più upsert che le combina. Ogni violazione di vincolo diventa un codice Prisma preciso, che il middleware degli errori (capitolo 8) traduce in uno status HTTP.

// create — violazione @unique → P2002 (409 nel middleware).
const cat = await client.category.create({ data: { name: "Accessori" } });

// update — una riga per campo univoco; se non esiste → P2025.
await client.product.update({ where: { id: 1 }, data: { price: "24.90" } });

// upsert — aggiorna se c'è, altrimenti crea.
await client.tag.upsert({
  where: { name: "gaming" },
  update: {},
  create: { name: "gaming" }
});

// delete — una riga per campo univoco.
await client.product.delete({ where: { id: 1 } });

Esistono anche createMany, updateMany e deleteMany per operazioni di massa: stesso where, più righe insieme.

Capitolo 5

Leggere le relazioni: include e select

Dentro include valgono le stesse opzioni di findMany (where, orderBy, take...): si può filtrare e ordinare anche la relazione, non solo la riga principale.

// 1:1 — profilo dell'utente.
await client.user.findUnique({ where: { id: 1 }, include: { profile: true } });

// 1:N — dentro include valgono LE STESSE OPZIONI di findMany.
await client.category.findUnique({
  where: { id: 1 },
  include: { products: { where: { inStock: true }, orderBy: { price: "asc" }, take: 3 } }
});

// select: SOLO i campi elencati (payload minimale).
await client.product.findMany({
  select: { id: true, name: true, category: { select: { name: true } } }
});

// _count: contare i collegati senza caricarli.
await client.category.findMany({ select: { name: true, _count: { select: { products: true } } } });

// M:N esplicita — include annidato attraverso il ponte: Order → OrderItem → Product.
await client.order.findUnique({
  where: { id: 1 },
  include: { items: { include: { product: { select: { name: true } } } } }
});

Nella stessa query scegli include oppure select allo stesso livello, mai insieme. Se usi select, indica al suo interno anche i campi della relazione.

Capitolo 6

Filtrare e scrivere attraverso le relazioni

Filtri per relazione: il where ragiona sulle righe collegate, non sulla riga principale.

// some: ALMENO UN prodotto collegato è esaurito.
await client.category.findMany({ where: { products: { some: { inStock: false } } } });

// every: TUTTI i prodotti collegati costano meno di 100.
await client.category.findMany({ where: { products: { every: { price: { lt: "100.00" } } } } });

// none: NESSUN prodotto collegato disponibile (incluse categorie vuote).
await client.category.findMany({ where: { products: { none: { inStock: true } } } });

// is / forma corta: prodotti la CUI categoria è "Periferiche".
await client.product.findMany({ where: { category: { name: "Periferiche" } } });
Operatore Domanda
some «ce n'è almeno uno che...?»
every «li hanno tutti...?»
none «nessuno di loro...?»
is / isNot versione singolare (1:1 e lato «uno» di 1:N)

Scritture annidate: una sola operazione tocca più tabelle.

// connect: collega a una riga esistente (invece di passare la FK a mano).
await client.product.create({
  data: { name: "Webcam", price: "49.90", category: { connect: { name: "Periferiche" } } }
});

// create annidato: la categoria E il prodotto insieme.
await client.category.create({
  data: { name: "Cuffie", products: { create: { name: "Cuffie Bluetooth", price: "39.90" } } }
});

// Attraverso il ponte: crea le righe ProductTag per il prodotto 1.
await client.product.update({
  where: { id: 1 },
  data: { tags: { create: [{ tagId: 1 }, { tagId: 2 }] } }
});

Capitolo 7

Aggregazioni, groupBy e transazioni

const stats = await client.product.aggregate({
  where: { inStock: true },
  _avg: { price: "0" },
  _max: { price: "0" },
  _count: true
});

// groupBy: prezzo medio per categoria.
await client.product.groupBy({
  by: ["categoryId"],
  _avg: { price: "0" },
  _count: { _all: true }
});

Transazioni: più scritture che devono riuscire tutte insieme, o nessuna. Dentro la funzione si usa tx, non client: scrivere con client per errore uscirebbe dalla transazione. 

const order = await client.$transaction(async (tx) => {
  const created = await tx.order.create({ data: { userId: 1 } });
  await tx.orderItem.create({
    data: { quantity: 1, unitPrice: "29.90", orderId: created.id, productId: 1 }
  });
  return created;
});

Capitolo 8

Il server Express: setup e gestione errori

Decimal non è serializzabile in JSON: ogni risposta che contiene un prezzo passa da un helper che chiama .toString(). Il middleware finale traduce i codici Prisma in status HTTP, una volta sola per tutta l'app.

import "dotenv/config";
import express from "express";
import { Prisma, OrderStatus } from "@prisma/client";
import { client } from "./prisma-client.js";

const app = express();
app.use(express.json());

// Decimal non è serializzabile in JSON: ogni risposta passa da questi helper.
const toProductJSON = (product) => ({
  ...product,
  price: product.price.toString(),
  // Con la M:N esplicita, include.tags sono righe del ponte: teniamo il tag.
  ...(product.tags && { tags: product.tags.map((pt) => pt.tag) })
});

const toOrderJSON = (order) => ({
  ...order,
  items: (order.items ?? []).map(({ unitPrice, ...item }) => ({
    ...item,
    unitPrice: unitPrice.toString()
  })),
  total: (order.items ?? []).reduce(
    (sum, item) => sum.add(item.unitPrice.mul(item.quantity)),
    new Prisma.Decimal(0)
  ).toString()
});

// Rotte qui sotto...

// Rotta inesistente → 404 JSON.
app.use((req, res) => res.status(404).json({ error: "Rotta non trovata." }));

// Middleware di errore (4 argomenti, ultimo della catena).
// Express 5 inoltra da solo le promise rifiutate delle rotte async.
app.use((err, req, res, next) => {
  console.error(err);

  if (err.type === "entity.parse.failed") {
    return res.status(400).json({ error: "Il corpo della richiesta non è JSON valido." });
  }

  if (err instanceof Prisma.PrismaClientKnownRequestError) {
    if (err.code === "P2025") return res.status(404).json({ error: "Record non trovato." });
    if (err.code === "P2002") return res.status(409).json({ error: "Valore già esistente: il campo è univoco." });
    if (err.code === "P2003") return res.status(409).json({ error: "Record collegato ad altri dati: operazione negata." });
  }

  const status = err.status ?? 500;
  res.status(status).json({ error: status === 500 ? "Errore interno del server." : err.message });
});

app.listen(3000, () => console.log("Store API su http://localhost:3000"));

Aggiungi lo script "dev": "node --watch server.js" in package.json (se non c'è) e avvia con pnpm dev.

Capitolo 9

CRUD prodotti

Le letture usano include: { category: true } per il prezzo con la categoria, e aggiungono i tag nel dettaglio:

app.get("/products", async (req, res) => {
  const products = await client.product.findMany({
    include: { category: true },
    orderBy: { createdAt: "desc" }
  });
  res.json(products.map(toProductJSON));
});

app.get("/products/:id", async (req, res) => {
  const id = Number(req.params.id);
  if (!Number.isInteger(id)) {
    return res.status(400).json({ error: "L'id deve essere un numero intero." });
  }
  const product = await client.product.findUnique({
    where: { id },
    include: { category: true, tags: { include: { tag: true } } }
  });
  if (!product) return res.status(404).json({ error: "Prodotto non trovato." });
  res.json(toProductJSON(product));
});

La creazione valida i campi a mano e controlla che la categoria esista prima di scrivere: 

app.post("/products", async (req, res) => {
  const { name, price, description, inStock, categoryId } = req.body ?? {};
  const errors = [];

  if (typeof name !== "string" || !name.trim()) errors.push("name è obbligatorio e deve essere una stringa non vuota.");
  if (typeof price !== "string" || !/^\d+(\.\d{1,2})?$/.test(price)) errors.push("price è obbligatorio, in formato '99.99'.");
  if (!Number.isInteger(categoryId)) errors.push("categoryId è obbligatorio e deve essere un intero.");

  if (errors.length === 0) {
    const category = await client.category.findUnique({ where: { id: categoryId } });
    if (!category) errors.push("La categoria indicata non esiste.");
  }
  if (errors.length > 0) {
    return res.status(400).json({ error: "Dati non validi.", details: errors });
  }

  const product = await client.product.create({
    data: { name, price, description, inStock: inStock ?? true, categoryId },
    include: { category: true }
  });
  res.status(201).json(toProductJSON(product));
});

PATCH costruisce data un campo alla volta: solo i campi presenti nel body vengono validati e scritti.

app.patch("/products/:id", async (req, res) => {
  const id = Number(req.params.id);
  if (!Number.isInteger(id)) return res.status(400).json({ error: "L'id deve essere un numero intero." });

  const { name, price, description, inStock, categoryId } = req.body ?? {};
  const data = {};

  if (name !== undefined) {
    if (typeof name !== "string" || !name.trim()) return res.status(400).json({ error: "name deve essere una stringa non vuota." });
    data.name = name;
  }
  if (price !== undefined) {
    if (typeof price !== "string" || !/^\d+(\.\d{1,2})?$/.test(price)) return res.status(400).json({ error: "price deve essere in formato '99.99'." });
    data.price = price;
  }
  if (description !== undefined) data.description = description;
  if (inStock !== undefined) {
    if (typeof inStock !== "boolean") return res.status(400).json({ error: "inStock deve essere true o false." });
    data.inStock = inStock;
  }
  if (categoryId !== undefined) {
    if (!Number.isInteger(categoryId)) return res.status(400).json({ error: "categoryId deve essere un intero." });
    const category = await client.category.findUnique({ where: { id: categoryId } });
    if (!category) return res.status(400).json({ error: "La categoria indicata non esiste." });
    data.categoryId = categoryId;
  }

  // P2025 → 404 e P2003 → 409 li gestisce il middleware.
  const product = await client.product.update({ where: { id }, data, include: { category: true } });
  res.json(toProductJSON(product));
});

app.delete("/products/:id", async (req, res) => {
  const id = Number(req.params.id);
  if (!Number.isInteger(id)) return res.status(400).json({ error: "L'id deve essere un numero intero." });

  // Se il prodotto compare in ordini, la FK Restrict di OrderItem
  // fa scattare P2003 → 409 dal middleware.
  await client.product.delete({ where: { id } });
  res.status(204).end();
});

Capitolo 11

CRUD ordini

Il prezzo lo decide il server, mai il client: POST /orders legge il prezzo attuale del prodotto e lo salva come unitPrice. Lettura e scrittura insieme richiedono una transazione interattiva.

app.get("/orders", async (req, res) => {
  const orders = await client.order.findMany({
    include: { items: { include: { product: { select: { id: true, name: true } } } } },
    orderBy: { createdAt: "desc" }
  });
  res.json(orders.map(toOrderJSON));
});

app.get("/orders/:id", async (req, res) => {
  const id = Number(req.params.id);
  if (!Number.isInteger(id)) return res.status(400).json({ error: "L'id deve essere un numero intero." });

  const order = await client.order.findUnique({
    where: { id },
    include: { items: { include: { product: { select: { id: true, name: true } } } } }
  });
  if (!order) return res.status(404).json({ error: "Ordine non trovato." });
  res.json(toOrderJSON(order));
});

app.post("/orders", async (req, res) => {
  const { userId, items } = req.body ?? {};
  const errors = [];

  if (!Number.isInteger(userId)) errors.push("userId è obbligatorio e deve essere un intero.");
  if (!Array.isArray(items) || items.length === 0) {
    errors.push("items è obbligatorio e deve essere un array non vuoto.");
  } else {
    items.forEach((item, i) => {
      if (!Number.isInteger(item?.productId)) errors.push(`items[${i}].productId deve essere un intero.`);
      if (!Number.isInteger(item?.quantity) || item.quantity < 1) errors.push(`items[${i}].quantity deve essere un intero >= 1.`);
    });
  }

  // L'utente deve esistere: stesso controllo esplicito già visto per categoryId.
  if (errors.length === 0) {
    const user = await client.user.findUnique({ where: { id: userId } });
    if (!user) errors.push("L'utente indicato non esiste.");
  }
  if (errors.length > 0) return res.status(400).json({ error: "Dati non validi.", details: errors });

  // Il prezzo lo decide il SERVER: snapshot del prezzo attuale del prodotto.
  // Lettura + scrittura insieme → transazione interattiva (tx, non client).
  const order = await client.$transaction(async (tx) => {
    const products = await tx.product.findMany({
      where: { id: { in: items.map((item) => item.productId) } }
    });
    const requested = new Set(items.map((item) => item.productId));
    if (products.length !== requested.size) {
      const err = new Error("Uno o più prodotti non esistono.");
      err.status = 400;
      throw err;
    }
    const priceById = new Map(products.map((p) => [p.id, p.price]));

    return tx.order.create({
      data: {
        userId,
        items: {
          create: items.map((item) => ({
            quantity: item.quantity,
            unitPrice: priceById.get(item.productId),
            productId: item.productId
          }))
        }
      },
      include: { items: { include: { product: { select: { id: true, name: true } } } } }
    });
  });

  res.status(201).json(toOrderJSON(order));
});

app.patch("/orders/:id", async (req, res) => {
  const id = Number(req.params.id);
  if (!Number.isInteger(id)) return res.status(400).json({ error: "L'id deve essere un numero intero." });

  const { status } = req.body ?? {};
  const valid = Object.values(OrderStatus);
  if (!valid.includes(status)) {
    return res.status(400).json({ error: `status deve essere uno di: ${valid.join(", ")}.` });
  }

  const order = await client.order.update({ where: { id }, data: { status } });
  res.json(order);
});

app.delete("/orders/:id", async (req, res) => {
  const id = Number(req.params.id);
  if (!Number.isInteger(id)) return res.status(400).json({ error: "L'id deve essere un numero intero." });

  // Cascade: le righe OrderItem vanno via con l'ordine.
  await client.order.delete({ where: { id } });
  res.status(204).end();
});

// Sostituisce TUTTI i tag di un prodotto: { "tagIds": [1, 3] }
app.put("/products/:id/tags", async (req, res) => {
  const id = Number(req.params.id);
  if (!Number.isInteger(id)) return res.status(400).json({ error: "L'id deve essere un numero intero." });

  const { tagIds } = req.body ?? {};
  if (!Array.isArray(tagIds) || !tagIds.every((t) => Number.isInteger(t))) {
    return res.status(400).json({ error: "tagIds è obbligatorio e deve essere un array di interi." });
  }

  const tags = await client.tag.findMany({ where: { id: { in: tagIds } } });
  if (tags.length !== new Set(tagIds).size) {
    return res.status(400).json({ error: "Uno o più tag non esistono." });
  }

  // Sostituzione atomica: via i collegamenti vecchi, dentro quelli nuovi.
  const product = await client.$transaction(async (tx) => {
    await tx.productTag.deleteMany({ where: { productId: id } });
    return tx.product.update({
      where: { id },
      data: { tags: { create: tagIds.map((tagId) => ({ tagId })) } },
      include: { tags: { include: { tag: true } } }
    });
  });

  res.json(toProductJSON(product));
});

Esercizio

Crea POST /products/:id/tags: a differenza della PUT sopra, aggiunge i tag indicati senza cancellare i collegamenti esistenti. 

app.post("/products/:id/tags", async (req, res) => {
  const id = Number(req.params.id);
  if (!Number.isInteger(id)) return res.status(400).json({ error: "L'id deve essere un numero intero." });

  const { tagIds } = req.body ?? {};
  if (!Array.isArray(tagIds) || !tagIds.every((t) => Number.isInteger(t))) {
    return res.status(400).json({ error: "tagIds è obbligatorio e deve essere un array di interi." });
  }

  const tags = await client.tag.findMany({ where: { id: { in: tagIds } } });
  if (tags.length !== new Set(tagIds).size) {
    return res.status(400).json({ error: "Uno o più tag non esistono." });
  }

  // skipDuplicates: se un tag è già collegato, l'unique del ponte non fa fallire tutto.
  await client.productTag.createMany({
    data: tagIds.map((tagId) => ({ productId: id, tagId })),
    skipDuplicates: true
  });

  const product = await client.product.findUnique({
    where: { id },
    include: { tags: { include: { tag: true } } }
  });
  res.json(toProductJSON(product));
});

Capitolo 13

Filtri e paginazione in query string

Sostituisce l'handler di GET /products del capitolo 9 con questa versione, che costruisce where solo con i filtri presenti nella query string:

// GET /products?maxPrice=100&available=true&categoryId=1&page=1&limit=10
app.get("/products", async (req, res) => {
  const page = Math.max(1, Number(req.query.page) || 1);
  const limit = Math.min(50, Math.max(1, Number(req.query.limit) || 10));

  // Il where si costruisce solo con i filtri presenti.
  const where = {};
  if (req.query.maxPrice) where.price = { lte: req.query.maxPrice };
  if (req.query.available === "true") where.inStock = true;
  if (req.query.available === "false") where.inStock = false;
  if (req.query.categoryId) where.categoryId = Number(req.query.categoryId);

  const [total, products] = await Promise.all([
    client.product.count({ where }),
    client.product.findMany({
      where,
      include: { category: true },
      orderBy: { createdAt: "desc" },
      skip: (page - 1) * limit,
      take: limit
    })
  ]);

  res.json({ page, limit, total, data: products.map(toProductJSON) });
});
