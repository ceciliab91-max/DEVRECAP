### Il modello mentale delle query
Ogni query Prisma ha la stessa forma: client.&lt;model&gt;.&lt;operazione&gt;({ opzioni }) e ritorna una Promise . Cambiano il model e l'operazione, non la forma. Lavoriamo sullo schema completo costruito nella dispensa precedente, Prisma: tipi, annotazioni e relazioni : nove model, con Category , Product , Tag , Order , User e Profile collegati da relazioni 1:1, 1:N e M:N esplicite. Le operazioni si dividono in due famiglie, a seconda che restituiscano una riga o molte: Famiglia Operazioni Una riga findUnique , findFirst , create , update , upsert , delete Molte righe findMany , createMany , updateMany , deleteMany , count , aggregate , groupBy Tre famiglie di opzioni coprono quasi tutto: where decide quali righe, orderBy / take / skip decidono ordine e quantità , include / select decidono quali campi e relazioni tornano indietro. const economici = await client.product.findMany({ where: { inStock: true }, // quali righe orderBy: { price: "asc" }, // ordine take: 5, // quantità include: { category: true } // relazioni });

### Leggere una riga e leggere liste
findUnique accetta solo campi @id o @unique ; findFirst accetta un filtro qualsiasi e usa orderBy per decidere chi è "il primo". // findUnique: SOLO per @id o campi @unique. const p1 = await client.product.findUnique({ where: { id: 1 } }); const c1 = await client.category.findUnique({ where: { name: "Periferiche" } }); // findUniqueOrThrow: se non trova lancia P2025 (lo converte il middleware in 404). const p2 = await client.product.findUniqueOrThrow({ where: { id: 1 } }); // findFirst: il primo che matcha un filtro qualsiasi (orderBy dice "primo" in che senso). const p3 = await client.product.findFirst({ where: { inStock: true }, orderBy: { price: "asc" } // il più economico disponibile }); Per le liste si aggiungono ordinamento multiplo, skip / take per la paginazione e count per il totale, separato dalla pagina di dati: const page = await client.product.findMany({ where: { inStock: true }, orderBy: [{ price: "desc" }, { name: "asc" }], // ordinamento multiplo skip: 0, take: 10 }); const total = await client.product.count({ where: { inStock: true } });

### I filtri
Più chiavi allo stesso livello di where sono in AND implicito; per un OR serve l'operatore esplicito OR . await client.product.findMany({ where: { name: { contains: "mouse" }, // LIKE '%mouse%' (MySQL è già case-insensitive) price: { gte: "20.00", lte: "100.00" }, // range: Decimal come STRINGA categoryId: { in: [1, 2] }, description: { not: null }, // chi HA la descrizione inStock: { not: false }, // Più chiave alla radice = AND implicito. Per OR: OR: [{ name: { startsWith: "Monitor" } }, { categoryId: 2 }] } }); Su MySQL non esiste mode: "insensitive" (solo PostgreSQL/MongoDB): non serve, la collation utf8mb4_unicode_ci delle tabelle Prisma è già case-insensitive.

### Scrivere
Le operazioni di scrittura su una riga singola sono quattro, più upsert che le combina. Ogni violazione di vincolo diventa un codice Prisma preciso, che il middleware degli errori (capitolo 8) traduce in uno status HTTP. // create — violazione @unique → P2002 (409 nel middleware). const cat = await client.category.create({ data: { name: "Accessori" } }); // update — una riga per campo univoco; se non esiste → P2025. await client.product.update({ where: { id: 1 }, data: { price: "24.90" } }); // upsert — aggiorna se c'è, altrimenti crea. await client.tag.upsert({ where: { name: "gaming" }, update: {}, create: { name: "gaming" } }); // delete — una riga per campo univoco. await client.product.delete({ where: { id: 1 } }); Esistono anche createMany , updateMany e deleteMany per operazioni di massa: stesso where , più righe insieme.

### Leggere le relazioni: include e select
Dentro include valgono le stesse opzioni di findMany ( where , orderBy , take ...): si può filtrare e ordinare anche la relazione, non solo la riga principale. // 1:1 — profilo dell'utente. await client.user.findUnique({ where: { id: 1 }, include: { profile: true } }); // 1:N — dentro include valgono LE STESSE OPZIONI di findMany. await client.category.findUnique({ where: { id: 1 }, include: { products: { where: { inStock: true }, orderBy: { price: "asc" }, take: 3 } } }); // select: SOLO i campi elencati (payload minimale). await client.product.findMany({ select: { id: true, name: true, category: { select: { name: true } } } }); // _count: contare i collegati senza caricarli. await client.category.findMany({ select: { name: true, _count: { select: { products: true } } } }); // M:N esplicita — include annidato attraverso il ponte: Order → OrderItem → Product. await client.order.findUnique({ where: { id: 1 }, include: { items: { include: { product: { select: { name: true } } } } } }); Nella stessa query scegli include oppure select allo stesso livello, mai insieme. Se usi select , indica al suo interno anche i campi della relazione.

### Filtrare e scrivere attraverso le relazioni
Filtri per relazione : il where ragiona sulle righe collegate, non sulla riga principale. // some: ALMENO UN prodotto collegato è esaurito. await client.category.findMany({ where: { products: { some: { inStock: false } } } }); // every: TUTTI i prodotti collegati costano meno di 100. await client.category.findMany({ where: { products: { every: { price: { lt: "100.00" } } } } }); // none: NESSUN prodotto collegato disponibile (incluse categorie vuote). await client.category.findMany({ where: { products: { none: { inStock: true } } } }); // is / forma corta: prodotti la CUI categoria è "Periferiche". await client.product.findMany({ where: { category: { name: "Periferiche" } } }); Operatore Domanda some «ce n'è almeno uno che...?» every «li hanno tutti...?» none «nessuno di loro...?» is / isNot versione singolare (1:1 e lato «uno» di 1:N) Scritture annidate : una sola operazione tocca più tabelle. // connect: collega a una riga esistente (invece di passare la FK a mano). await client.product.create({ data: { name: "Webcam", price: "49.90", category: { connect: { name: "Periferiche" } } } }); // create annidato: la categoria E il prodotto insieme. await client.category.create({ data: { name: "Cuffie", products: { create: { name: "Cuffie Bluetooth", price: "39.90" } } } }); // Attraverso il ponte: crea le righe ProductTag per il prodotto 1. await client.product.update({ where: { id: 1 }, data: { tags: { create: [{ tagId: 1 }, { tagId: 2 }] } } });

### Il server Express: setup e gestione errori
Decimal non è serializzabile in JSON: ogni risposta che contiene un prezzo passa da un helper che chiama .toString() . Il middleware finale traduce i codici Prisma in status HTTP, una volta sola per tutta l'app. import "dotenv/config"; import express from "express"; import { Prisma, OrderStatus } from "@prisma/client"; import { client } from "./prisma-client.js"; const app = express(); app.use(express.json()); // Decimal non è serializzabile in JSON: ogni risposta passa da questi helper. const toProductJSON = (product) =&gt; ({ ...product, price: product.price.toString(), // Con la M:N esplicita, include.tags sono righe del ponte: teniamo il tag. ...(product.tags &amp;&amp; { tags: product.tags.map((pt) =&gt; pt.tag) }) }); const toOrderJSON = (order) =&gt; ({ ...order, items: (order.items ?? []).map(({ unitPrice, ...item }) =&gt; ({ ...item, unitPrice: unitPrice.toString() })), total: (order.items ?? []).reduce( (sum, item) =&gt; sum.add(item.unitPrice.mul(item.quantity)), new Prisma.Decimal(0) ).toString() }); // Rotte qui sotto... // Rotta inesistente → 404 JSON. app.use((req, res) =&gt; res.status(404).json({ error: "Rotta non trovata." })); // Middleware di errore (4 argomenti, ultimo della catena). // Express 5 inoltra da solo le promise rifiutate delle rotte async. app.use((err, req, res, next) =&gt; { console.error(err); if (err.type === "entity.parse.failed") { return res.status(400).json({ error: "Il corpo della richiesta non è JSON valido." }); } if (err instanceof Prisma.PrismaClientKnownRequestError) { if (err.code === "P2025") return res.status(404).json({ error: "Record non trovato." }); if (err.code === "P2002") return res.status(409).json({ error: "Valore già esistente: il campo è univoco." }); if (err.code === "P2003") return res.status(409).json({ error: "Record collegato ad altri dati: operazione negata." }); } const status = err.status ?? 500; res.status(status).json({ error: status === 500 ? "Errore interno del server." : err.message }); }); app.listen(3000, () =&gt; console.log("Store API su http://localhost:3000")); Aggiungi lo script "dev": "node --watch server.js" in package.json (se non c'è) e avvia con pnpm dev .

### Filtri e paginazione in query string
Sostituisce l'handler di GET /products del capitolo 9 con questa versione, che costruisce where solo con i filtri presenti nella query string: // GET /products?maxPrice=100&amp;available=true&amp;categoryId=1&amp;page=1&amp;limit=10 app.get("/products", async (req, res) =&gt; { const page = Math.max(1, Number(req.query.page) || 1); const limit = Math.min(50, Math.max(1, Number(req.query.limit) || 10)); // Il where si costruisce solo con i filtri presenti. const where = {}; if (req.query.maxPrice) where.price = { lte: req.query.maxPrice }; if (req.query.available === "true") where.inStock = true; if (req.query.available === "false") where.inStock = false; if (req.query.categoryId) where.categoryId = Number(req.query.categoryId); const [total, products] = await Promise.all([ client.product.count({ where }), client.product.findMany({ where, include: { category: true }, orderBy: { createdAt: "desc" }, skip: (page - 1) * limit, take: limit }) ]); res.json({ page, limit, total, data: products.map(toProductJSON) }); });
