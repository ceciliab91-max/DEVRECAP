### LLM stateless e storico dei messaggi
Un LLM è stateless . Questo significa che una chiamata a model.invoke() non conserva automaticamente ciò che è accaduto nella chiamata precedente. ✕ HumanMessage #1 "Mi chiamo Samuel" model.invoke() #1 Risposta 1 HumanMessage #2 "Genesi del mio nome?" model.invoke() #2 Risposta 2 nessuna memoria condivisa tra le due chiamate Due chiamate indipendenti: la seconda non sa nulla della prima, a meno che non gliela inviamo esplicitamente. Esempio concettuale Immaginiamo queste due chiamate separate: Prima chiamata: Utente: "Ciao, mi chiamo Samuel." Seconda chiamata: Utente: "Qual è la genesi del mio nome?" Se nella seconda chiamata non inviamo anche il primo messaggio, il modello non riceve l'informazione che il nome dell'utente è Samuel. Esempio stateless Crea il file 01-stateless.js . // Carica la chiave API dal file .env. import 'dotenv/config'; // ChatAnthropic permette di usare Claude tramite LangChain. import { ChatAnthropic } from '@langchain/anthropic'; // HumanMessage rappresenta ogni messaggio scritto dall'utente. import { HumanMessage } from 'langchain'; // Creiamo il modello indicando il modello Anthropic da usare. const model = new ChatAnthropic({ model: 'claude-haiku-4-5-20251001' }); try { // Prima chiamata: il modello riceve un array con un solo messaggio. const firstResponse = await model.invoke([ new HumanMessage('Ciao, mi chiamo Samuel.') ]); console.log('PRIMA RISPOSTA:'); console.log(firstResponse.content); // Seconda chiamata: creiamo un nuovo array con un nuovo messaggio. // Il modello non riceve il messaggio precedente. const secondResponse = await model.invoke([ new HumanMessage('Qual è la genesi del mio nome?') ]); console.log('\nSECONDA RISPOSTA:'); console.log(secondResponse.content); } catch (error) { // Gestiamo eventuali problemi di configurazione, rete o autenticazione. console.error('Errore durante la conversazione:', error); } Eseguiamo il file. # dotenv è importato nel file: non servono flag aggiuntivi. node 01-stateless.js Cosa osservare Le due invocazioni sono indipendenti. Nella seconda chiamata il modello riceve solamente: Qual è la genesi del mio nome? Non riceve il messaggio: Ciao, mi chiamo Samuel. Il modello potrebbe comunque conoscere il significato del nome Samuel, ma non perché lo ha memorizzato durante la prima chiamata. Lo sa perché il nome è presente nella sua conoscenza generale. Per vedere più chiaramente il problema, possiamo usare una parola inventata. // Carica la chiave API dal file .env. import 'dotenv/config'; // Questo esempio usa una parola inventata per rendere evidente // che il modello non conserva automaticamente memoria tra due chiamate. import { ChatAnthropic } from '@langchain/anthropic'; import { HumanMessage } from 'langchain'; const model = new ChatAnthropic({ model: 'claude-haiku-4-5-20251001' }); try { // Il modello riceve la parola segreta soltanto in questa chiamata. await model.invoke([ new HumanMessage('Ricorda che la parola segreta di oggi è marmotta-blu.') ]); // Questa è una nuova richiesta indipendente. // La parola marmotta-blu non viene reinviata. const response = await model.invoke([ new HumanMessage('Qual è la parola segreta di oggi?') ]); console.log(response.content); } catch (error) { console.error('Errore durante l’esempio stateless:', error); }

### Gestire lo storico della chat
Per permettere al modello di conoscere i messaggi precedenti, dobbiamo conservare manualmente lo storico della conversazione. Lo storico sarà un array chiamato messages . L'array conterrà: i messaggi dell'utente, rappresentati da HumanMessage ; le risposte del modello, rappresentate da AIMessage . Non dobbiamo creare manualmente l' AIMessage : lo riceviamo come risultato di model.invoke() . messages.push(...) nuovo turno invia i 3 messaggi messages.push(...) messages[0] — HumanMessage "Ciao, mi chiamo Samuel." messages[1] — AIMessage risposta salvata nello storico messages[2] — HumanMessage "Qual è la genesi del mio nome?" Il modello risponde ora conosce anche messages[0] e [1] messages[3] — AIMessage nuova risposta salvata nello storico Ogni invoke() riceve l'intero array: per questo il modello del secondo turno può collegare "il mio nome" al nome Samuel. Esempio con storico Crea il file 02-storico-chat.js . // Carica la chiave API dal file .env. import 'dotenv/config'; // ChatAnthropic permette di usare Claude tramite LangChain. import { ChatAnthropic } from '@langchain/anthropic'; // HumanMessage rappresenta un messaggio dell'utente. import { HumanMessage } from 'langchain'; // Creiamo il modello Anthropic. const model = new ChatAnthropic({ model: 'claude-haiku-4-5-20251001' }); // Questo array contiene l'intero storico della conversazione. const messages = []; try { // Aggiungiamo il primo messaggio dell'utente allo storico. messages.push( new HumanMessage('Ciao, mi chiamo Samuel.') ); // Inviamo tutto lo storico al modello. const firstResponse = await model.invoke(messages); // Salviamo nello storico anche la risposta del modello. // In questo modo il prossimo turno conoscerà sia domanda sia risposta. messages.push(firstResponse); console.log('ASSISTENTE:'); console.log(firstResponse.content); // Aggiungiamo il secondo messaggio dell'utente allo stesso array. messages.push( new HumanMessage('Qual è la genesi del mio nome?') ); // Inviamo nuovamente l'intero storico, non solo l'ultima domanda. const secondResponse = await model.invoke(messages); // Salviamo anche la seconda risposta nel caso la chat continui. messages.push(secondResponse); console.log('\nASSISTENTE:'); console.log(secondResponse.content); // Mostriamo quanti messaggi sono stati salvati nello storico. console.log(`\nMessaggi nello storico: ${messages.length}`); } catch (error) { // Gestiamo eventuali errori durante la chiamata al modello. console.error('Errore durante la gestione dello storico:', error); } Eseguiamo il file. # dotenv è importato nel file: non servono flag aggiuntivi. node 02-storico-chat.js Come cambia lo storico? Dopo il primo messaggio dell'utente: 1. HumanMessage: "Ciao, mi chiamo Samuel." Dopo la risposta del modello: 1. HumanMessage: "Ciao, mi chiamo Samuel." 2. AIMessage: "Ciao Samuel, piacere di conoscerti..." Dopo il secondo messaggio dell'utente: 1. HumanMessage: "Ciao, mi chiamo Samuel." 2. AIMessage: "Ciao Samuel, piacere di conoscerti..." 3. HumanMessage: "Qual è la genesi del mio nome?" A questo punto il modello può collegare l'espressione “il mio nome” al nome Samuel, perché riceve anche il primo messaggio. Attenzione: lo storico cresce A ogni nuovo turno aggiungiamo messaggi nell'array. Questo comporta due conseguenze: aumentano i token inviati al modello; una conversazione molto lunga può superare il limite di contesto del modello. Per ora gestiamo manualmente lo storico, perché è il modo più semplice per capire come funziona. In futuro potremo selezionare solo i messaggi più importanti oppure creare un riassunto della conversazione.

### Il limite dei dati aggiornati
Un LLM è molto bravo a generare testo, spiegare concetti, riformulare contenuti e ragionare sui dati che riceve. Tuttavia non può conoscere automaticamente informazioni aggiornate in tempo reale. Per esempio, proviamo a chiedere: Che tempo fa a Pisa? Crea il file 03-senza-tool.js . // Carica la chiave API dal file .env. import 'dotenv/config'; // ChatAnthropic permette di inviare messaggi a un modello Anthropic. import { ChatAnthropic } from '@langchain/anthropic'; // HumanMessage rappresenta il messaggio scritto dall'utente. import { HumanMessage } from 'langchain'; // Creiamo il modello Anthropic. const model = new ChatAnthropic({ model: 'claude-haiku-4-5-20251001' }); try { // Il modello riceve soltanto la domanda dell'utente. // Non riceve dati meteorologici in tempo reale. const response = await model.invoke([ new HumanMessage('Che tempo fa a Pisa in questo momento?') ]); console.log(response.content); } catch (error) { console.error('Errore durante la richiesta meteo:', error); } Il modello potrebbe rispondere che non possiede dati in tempo reale oppure potrebbe fornire informazioni generiche sul clima di Pisa. Per ottenere dati aggiornati dobbiamo dare al modello uno strumento che possa recuperare informazioni dall'esterno. Questo strumento viene chiamato tool .

### Tool e Zod
Un tool è una funzione JavaScript che un agente può decidere di usare. Un tool è composto da quattro parti principali: una funzione JavaScript che contiene la logica; un nome tecnico; una descrizione per il modello; uno schema che descrive gli argomenti richiesti. Esempio concettuale Un tool meteo potrebbe ricevere una città: get_weather({ city: "Pisa" }) Il modello non esegue direttamente il codice JavaScript. Il modello decide di richiamare il tool indicando gli argomenti; LangChain esegue la funzione; infine il risultato viene reinviato al modello. Utente Agente Il modello decide di usare un tool get_weather({ city: "Pisa" }) LangChain esegue la funzione Il tool restituisce un risultato Il modello risponde all'utente Il modello non esegue mai direttamente il codice JavaScript: decide solo quale tool chiamare e con quali argomenti. Che cos'è Zod? Zod è una libreria per descrivere e validare dati JavaScript. Nel nostro caso useremo Zod per dire che il tool meteo richiede un oggetto con una proprietà city di tipo stringa. // z.object() descrive un oggetto. // La proprietà city deve contenere una stringa. const getWeatherSchema = z.object({ city: z.string() }); Se il modello costruisse una chiamata non valida, lo schema aiuta LangChain a rilevare il problema.

### Creare il tool meteo mock
In questa prima lezione non useremo una vera API meteorologica. Creeremo invece un mock : una funzione che simula un servizio meteo e restituisce sempre lo stesso risultato. Questo ci permette di concentrarci sul funzionamento di tool e agenti senza introdurre API key aggiuntive, richieste HTTP o gestione di dati esterni. Struttura delle cartelle Creiamo una cartella chiamata tools . langchain-prima-parte/ ├── tools/ │ └── getWeather.js ├── .env ├── .env.example ├── .gitignore ├── index.js ├── 01-stateless.js ├── 02-storico-chat.js ├── 03-senza-tool.js ├── 04-agente-meteo.js └── package.json Tool get_weather Crea il file tools/getWeather.js . // tool() trasforma una funzione JavaScript in un tool utilizzabile da LangChain. import { tool } from 'langchain'; // Zod permette di descrivere e validare gli argomenti del tool. import { z } from 'zod'; /** * Questa funzione contiene la logica del tool meteo. * * Per questa prima lezione è un mock: non chiama servizi esterni * e restituisce sempre lo stesso risultato, indipendentemente dalla città. * * @param {{ city: string }} parameters - Oggetto ricevuto dal tool. * @returns {Promise&lt;string&gt;} Una frase con il meteo simulato. */ async function getWeatherFunction({ city }) { // Usiamo city solo per evitare un parametro inutilizzato. // Nella versione mock non cambia il risultato restituito. void city; // Il tool restituisce sempre una stringa, non un oggetto JSON. return 'Il meteo è sereno con una temperatura di 22 °C. Dati forniti da un mock didattico.'; } // Lo schema è separato dalla funzione del tool. // Specifica che il tool richiede un oggetto con una proprietà city di tipo stringa. const getWeatherSchema = z.object({ city: z.string().describe('La città di cui si vuole conoscere il meteo.') }); // Creiamo il tool collegando la funzione alla sua configurazione. const getWeather = tool(getWeatherFunction, { // Nome tecnico che il modello utilizza per richiamare il tool. name: 'get_weather', // Descrizione usata dal modello per capire quando usare il tool. description: 'Restituisce il meteo attuale di una città italiana.', // Schema Zod definito separatamente. schema: getWeatherSchema }); // Esportiamo il tool per poterlo importare nel file dell'agente. export default getWeather; Parti del tool Parte Ruolo getWeatherFunction Contiene la logica eseguita quando il tool viene chiamato getWeatherSchema Definisce gli argomenti che il tool si aspetta name È il nome tecnico usato dal modello per richiamare il tool description Spiega al modello quando è opportuno usare il tool tool(...) Collega funzione, schema e metadati creando il tool LangChain Perché il mock restituisce sempre una stringa? Il nostro obiettivo non è ancora costruire un servizio meteo realistico. Vogliamo solo dimostrare che: l'utente fa una domanda; l'agente riconosce che serve il tool; LangChain esegue getWeatherFunction() ; la funzione restituisce una stringa; il modello usa quella stringa per creare una risposta finale.

### Creare un agente LangChain
Un agente collega un modello a uno o più tool. A differenza di una chiamata diretta a model.invoke() , l'agente può decidere se un tool è necessario per rispondere alla richiesta dell'utente. Crea il file 04-agente-meteo.js . // Carica la chiave API dal file .env. import 'dotenv/config'; // ChatAnthropic permette di usare Claude tramite LangChain. import { ChatAnthropic } from '@langchain/anthropic'; // createAgent crea un agente che può utilizzare uno o più tool. // HumanMessage rappresenta il messaggio inviato dall'utente. import { createAgent, HumanMessage } from 'langchain'; // Importiamo il tool meteo creato nella cartella tools. import getWeather from './tools/getWeather.js'; // Creiamo il modello indicando soltanto il modello Anthropic scelto. const model = new ChatAnthropic({ model: 'claude-haiku-4-5-20251001' }); // Creiamo un agente e gli rendiamo disponibile il tool get_weather. const agent = createAgent({ model, tools: [getWeather], // Il system prompt contiene istruzioni permanenti per l'agente. systemPrompt: ` Sei un assistente meteorologico didattico. Quando l'utente chiede il meteo di una città, usa il tool get_weather. Dichiara sempre che i dati restituiti provengono da un mock didattico. ` }); try { // Anche agent.invoke() riceve sempre un array di HumanMessage. // Non usiamo l'oggetto abbreviato con role e content. const result = await agent.invoke({ messages: [ new HumanMessage('Che tempo fa a Pisa?') ] }); // L'ultimo messaggio prodotto dall'agente è la risposta finale. const finalMessage = result.messages.at(-1); console.log('RISPOSTA FINALE DELL’AGENTE:'); console.log(finalMessage.content); } catch (error) { // Gestiamo possibili problemi di configurazione, rete o autenticazione. console.error('Errore durante l’esecuzione dell’agente:', error); } Eseguiamo il file. # dotenv è importato nel file: non servono flag aggiuntivi. node 04-agente-meteo.js Cosa accade durante l'esecuzione? ### Riepilogo
In questa prima parte abbiamo visto che: LangChain aiuta a lavorare con LLM, messaggi, tool e agenti. ChatAnthropic è il componente usato per comunicare con Anthropic. Il modello viene creato indicando la proprietà model . Ogni chiamata a model.invoke() riceve sempre un array di HumanMessage . Un LLM è stateless: non conserva automaticamente le chiamate precedenti. Per creare una conversazione dobbiamo mantenere un array chiamato messages . Dopo ogni chiamata dobbiamo aggiungere allo storico anche la risposta del modello. Un LLM non possiede automaticamente dati aggiornati, come il meteo in tempo reale. Un tool è una funzione che un agente può scegliere di usare. Zod descrive e valida gli argomenti che il tool riceve. Un agente collega il modello ai tool disponibili. Anche agent.invoke() riceve messaggi rappresentati con HumanMessage . Il nostro tool meteo mock ha funzione e schema separati e restituisce sempre una stringa.
