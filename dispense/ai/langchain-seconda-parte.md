### Le chiamate a tool: come funziona il ciclo
Un agente non chiama un tool a caso: quando gli serve un'informazione che non ha, si ferma, chiama il tool giusto e riprende a ragionare con il risultato in mano. Nella prima parte abbiamo creato il tool get_weather e lo abbiamo collegato a un agente con createAgent() . Il modello legge la description del tool per capire quando usarlo, poi genera i parametri richiesti dallo schema e li passa alla funzione. Il ciclo si ripete ogni volta che serve: l'agente può chiamare più tool, uno dopo l'altro, prima di rispondere. Regola da ricordare: un tool deve restituire sempre una stringa . Se il dato è un oggetto o un array, va convertito con JSON.stringify() prima del return . Ho bisogno di dati Elabora e risponde Domanda dell'utente Agente (LLM) Chiama il tool get_weather(city, unit) Riceve il risultato return sempre una stringa Agente (LLM) Risposta finale L'agente torna sempre dal modello dopo aver ricevuto il risultato del tool: non decide da solo la risposta finale finché l'LLM non la conferma. Il tool get_weather import { tool } from "langchain"; import { z } from 'zod'; const schema = z.object({ city: z.string().describe('La città di cui vuoi le informazioni'), unit: z.string().describe("L'unità di misura con cui vuoi che sia espresso il risultato") }); const toolFunction = async ({ city, unit }) => { // Il valore restituito dal tool DEVE essere sempre una stringa return `Il tempo a ${city} è costantemente a 28 ${unit}`; } const getWeather = tool(toolFunction, { name: "get_weather", description: "Questo tool serve quando hai bisogno di informazioni sul meteo", schema }); export { getWeather }; Esercizio Aggiungi al tool getWeather un secondo campo nella stringa restituita: una previsione inventata per il giorno successivo (es. "domani pioggia"). Mostra soluzione const toolFunction = async ({ city, unit }) => { return `Il tempo a ${city} è costantemente a 28 ${unit}. Domani: pioggia debole.`; }

### Lo schema Zod: cosa descrive e dove si usa
Zod descrive la forma dei dati. In LangChain si usa in due punti diversi: nello schema di un tool (i parametri in input) e nel responseFormat di un agente (la forma della risposta finale). Nel tool, lo schema dice al modello quali parametri deve generare per chiamare la funzione: z.string() , z.number() , z.enum([...]) e così via, ognuno con un .describe() che spiega al modello a cosa serve quel campo. Nel responseFormat lo stesso linguaggio serve per un altro scopo: vincolare la risposta finale dell'agente a una forma precisa, invece di lasciarla libera. Vedremo un esempio completo nel prossimo capitolo. Regola da ricordare: Anthropic richiede che lo schema abbia sempre type: object alla radice. Uno z.array() come radice non è supportato: va sempre incapsulato in un z.object() . Schema Zod z.object({ ... }) Nel tool parametri in input id: z.number() Nel responseFormat forma della risposta sentiment: z.enum([...]) Stesso linguaggio (Zod), due scopi diversi: parametri in ingresso al tool, oppure forma della risposta finale dell'agente. Esempio: schema per un tool con parametro numerico const schema = z.object({ id: z.number().describe("l'ID del prodotto di cui vuoi informazioni") }); Esercizio Scrivi lo schema Zod per un tool che cerca un prodotto per nome, con un unico parametro nameSearch di tipo stringa. Mostra soluzione const schema = z.object({ nameSearch: z.string().describe("il nome del prodotto da cercare") });

### Costruire un agente con createAgent
createAgent mette insieme tre ingredienti: un modello , uno o più tool e, facoltativamente, un systemPrompt che definisce il comportamento dell'agente. Il modello è l'istanza del chat model (es. ChatAnthropic ), i tool sono un array (anche vuoto, se l'agente non ne usa nessuno) e il systemPrompt è un testo che orienta il tono e il ruolo dell'agente prima ancora che arrivi la prima domanda. Una volta creato, l'agente si usa con agent.invoke({ messages: [...] }) . model models/anthropic.js tools [] oppure [tool1, ...] systemPrompt opzionale createAgent({ ... }) Agente pronto agent.invoke({ messages }) I tre ingredienti di createAgent: modello, tool e system prompt. Il risultato è un agente pronto a ricevere messaggi con invoke(). Un agente minimo, senza tool import { createAgent, HumanMessage } from "langchain"; import model from "./models/anthropic.js"; const agent = createAgent({ model, tools: [], systemPrompt: "Sei un assistente disponibile e sintetico." }); const response = await agent.invoke({ messages: [new HumanMessage("Ciao, come stai?")] }); console.log(response.messages.at(-1).content); Esercizio Cambia il systemPrompt dell'agente qui sopra per dargli una personalità diversa (es. "rispondi sempre in rima") e osserva come cambia la risposta. Mostra soluzione const agent = createAgent({ model, tools: [], systemPrompt: "Sei un assistente che risponde sempre in rima, in italiano." });

### Output strutturato con responseFormat
Quando imposti responseFormat su un agente, la sua risposta finale deve avere quella forma. Il modello farà di tutto per soddisfare lo schema, incluso chiamare i tool necessari. Con responseFormat impostato, la risposta non va più letta da response.messages.at(-1).content (che conterrebbe JSON grezzo), ma dal campo response.structuredResponse , già validato secondo lo schema Zod. Vediamo un caso concreto: un agente che analizza una recensione di una pizzeria e restituisce sentiment, voto e un breve feedback, sempre nella stessa forma. Analizzatore di recensioni import "dotenv/config"; import { ChatAnthropic } from "@langchain/anthropic"; import { createAgent, HumanMessage } from "langchain"; import { getWeather } from "./tools/getWeather.js"; import { z } from 'zod'; const model = new ChatAnthropic({ model: 'claude-haiku-4-5', apiKey: process.env.ANTHROPIC_API_KEY }); const agent = createAgent({ model, tools: [getWeather], systemPrompt: "Ciao sei un analizzatore di recensioni online della pizzeria da Antonio", responseFormat: z.object({ sentiment: z.enum(['positiva', 'negativa']), score: z.number().min(1).max(5), feedback: z.string() }) }); const recensione = "La cottura della pizza era ottima, come pure il servizio, do il massimo dei voti"; const response = await agent.invoke({ messages: [new HumanMessage(` Analizza la seguente recensione: - dimmi se è (negativa/positiva) - un eventuale valore in gradimento da 1 a 5 ${recensione} `)] }); // Con responseFormat leggiamo structuredResponse, non messages.at(-1).content console.log(response.structuredResponse); // { sentiment: 'positiva', score: 5, feedback: '...' } Nota che l'agente ha comunque un tool ( getWeather ) tra le mani: responseFormat vincola solo la forma finale della risposta, non impedisce all'agente di usare i tool durante il ragionamento. Esercizio Aggiungi allo schema un campo categoria con z.enum(['cibo', 'servizio', 'ambiente']) e stampa solo quel campo dalla risposta. Mostra soluzione responseFormat: z.object({ sentiment: z.enum(['positiva', 'negativa']), score: z.number().min(1).max(5), feedback: z.string(), categoria: z.enum(['cibo', 'servizio', 'ambiente']) }) // ... console.log(response.structuredResponse.categoria);

### Più agenti con personalità diverse: Psy, Psyco e Mediator
Stesso modello, systemPrompt diversi: bastano per ottenere punti di vista opposti sulla stessa domanda. Un terzo agente può poi leggere entrambe le risposte e sintetizzarle. È una versione semplificata del pattern Debate : più "esperti" rispondono alla stessa domanda con prospettive diverse, poi un agente (il "giudice" o, come lo chiamiamo qui, il Mediator ) confronta le risposte e propone una sintesi. Creiamo due agenti con personalità agli antipodi: L'agente psy import { createAgent } from "langchain"; import anthropicModel from '../models/anthropic.js'; const agentPsy = createAgent({ model: anthropicModel, systemPrompt: ` Sei uno pscichiatra che interpreta alla lettera la filosofia di Jung. Sai interpretare i sogni come Freud e suggerisce sempre problemi affettivi con la figura genitoriale ` }); export default agentPsy; L'agente psyco import { createAgent } from "langchain"; import anthropicModel from '../models/anthropic.js'; const agentPsyco = createAgent({ model: anthropicModel, systemPrompt: ` Sei uno psicopatico fuori di testa, che ha sempre idee fuori dal comune. Rispondi sempre in tono crucciato e suggeriscimi sempre modi nuovi per creare bug nel mio codice ` }); export default agentPsyco; L'agente mediator import { createAgent } from "langchain"; import anthropicModel from '../models/anthropic.js'; const agentMediator = createAgent({ model: anthropicModel, systemPrompt: ` Sei un agente che deve analizzare le opinioni di due agenti molto diversi, capirne i pro e contro e suggerire una soluzione che metta d'accordo entrambi. ` }); export default agentMediator; La domanda viene inviata a entrambi gli agenti in modo indipendente. Ogni risposta è solo testo (nessun responseFormat qui), quindi la leggiamo da response.messages.at(-1).content . Il Mediator riceve infine la domanda originale e entrambe le risposte, per poterle confrontare. Orchestrazione import "dotenv/config"; import { HumanMessage } from "langchain"; import psyAgent from './agents/psy.js'; import psycoAgent from './agents/psyco.js'; import mediatorAgent from './agents/mediator.js'; const question = `Mi dici una possibile alternativa al petrolio`; const responsePsyco = await psycoAgent.invoke({ messages: [new HumanMessage(question)] }); const responsePsycoText = responsePsyco.messages.at(-1).content; const responsePsy = await psyAgent.invoke({ messages: [new HumanMessage(question)] }); const responsePsyText = responsePsy.messages.at(-1).content; const responseMediator = await mediatorAgent.invoke({ messages: [new HumanMessage(` Domanda dell'utente: ${question} Risposta PSYCO: ${responsePsycoText} Risposta PSY: ${responsePsyText} Fai un recap della discussione e dimmi il risultato finale della domanda `)] }); console.log(responseMediator.messages.at(-1).content); Esercizio Aggiungi un terzo agente esperto (es. un ingegnere pragmatico, senza fronzoli) e passa anche la sua risposta al Mediator insieme alle altre due. Mostra soluzione // agents/engineer.js import { createAgent } from "langchain"; import anthropicModel from '../models/anthropic.js'; const agentEngineer = createAgent({ model: anthropicModel, systemPrompt: ` Sei un ingegnere pragmatico: rispondi in modo tecnico, concreto, senza fronzoli e citando sempre un limite pratico della soluzione. ` }); export default agentEngineer; // main2.js (estratto) const responseEngineer = await engineerAgent.invoke({ messages: [new HumanMessage(question)] }); const responseEngineerText = responseEngineer.messages.at(-1).content; const responseMediator = await mediatorAgent.invoke({ messages: [new HumanMessage(` Domanda dell'utente: ${question} Risposta PSYCO: ${responsePsycoText} Risposta PSY: ${responsePsyText} Risposta ENGINEER: ${responseEngineerText} Fai un recap della discussione e dimmi il risultato finale della domanda `)] });

### Organizzare il progetto: models/, agents/, tools/
Separare modelli, agenti e tool in cartelle dedicate rende il codice più facile da estendere man mano che il progetto cresce. Con più agenti e più tool, tenere tutto in un unico file diventa presto scomodo. Convenzione semplice ed efficace: models/ — un file per provider, ognuno esporta un'istanza già configurata ( anthropic.js , mistral.js , openai.js ). Cambiare provider vuol dire importare un file diverso, non toccare la logica dell'agente. agents/ — un file per agente, ognuno esporta l'agente già pronto con createAgent() , i suoi tool e il suo systemPrompt . tools/ — un file per tool, ognuno esporta la funzione creata con tool() e il suo schema Zod. Struttura delle cartelle progetto/ ├── models/ │ ├── anthropic.js │ ├── mistral.js │ └── openai.js ├── agents/ │ └── generic.js ├── tools/ │ ├── getWeather.js │ ├── getProducts.js │ ├── getProductInfo.js │ └── searchProduct.js ├── data/ │ └── db.js └── server.js Un modello per provider // models/anthropic.js import { ChatAnthropic } from "@langchain/anthropic"; const model = new ChatAnthropic({ model: 'claude-haiku-4-5', apiKey: process.env.ANTHROPIC_API_KEY }); export default model; // models/mistral.js import { ChatMistralAI } from "@langchain/mistralai"; const model = new ChatMistralAI({ apiKey: process.env.MISTRAL_API_KEY }); export default model; Un agente che importa modello e tool // agents/generic.js import { createAgent } from "langchain"; import mistralModel from '../models/mistral.js'; import { getWeather } from '../tools/getWeather.js'; import { getProductInfo } from '../tools/getProductInfo.js'; import { searchProduct } from '../tools/searchProduct.js'; const genericAgent = createAgent({ model: mistralModel, tools: [ getWeather, getProductInfo, searchProduct, ], }); export default genericAgent; Cambiare provider all'agente generico è ora un'unica riga: basta importare anthropicModel o openAiModel al posto di mistralModel . Esercizio Crea models/openai.js seguendo lo stesso schema di anthropic.js , poi cambia l'import in agents/generic.js per usare OpenAI al posto di Mistral. Mostra soluzione // models/openai.js import { ChatOpenAI } from "@langchain/openai"; const model = new ChatOpenAI({ model: 'gpt-3.5-turbo', apiKey: process.env.OPENAI_API_KEY, }); export default model; // agents/generic.js import openAiModel from '../models/openai.js'; const genericAgent = createAgent({ model: openAiModel, tools: [getWeather, getProductInfo, searchProduct], });

### Express: la rotta GET /ai
Una rotta Express può inoltrare la domanda dell'utente direttamente all'agente e restituirne la risposta: è il modo più semplice per esporre un agente come API. Installiamo Express e creiamo un piccolo server con una rotta che legge la domanda dalla query string e la inoltra all'agente Generico (quello di agents/generic.js , senza vincoli di responseFormat ). pnpm add express dotenv server.js import 'dotenv/config'; import express from 'express'; import aiRouter from './routers/aiRouter.js'; const app = express(); const PORT = process.env.PORT; app.use(express.json()); app.use('/ai', aiRouter); app.listen(PORT, (error) => { if (error) { console.error(error); } else { console.log(`Server in ascolto sulla porta ${PORT}`); } }); routers/aiRouter.js — GET /ai import { Router } from "express"; import genericAgent from '../agents/generic.js'; import { HumanMessage } from "langchain"; const router = Router(); // http://localhost:3000/ai?richiesta=Che tempo fa a Pisa router.get('/', async (req, res) => { const richiesta = req.query.richiesta; const response = await genericAgent.invoke({ messages: [new HumanMessage(richiesta)] }); const responseText = response.messages.at(-1).content; res.send(responseText); }); export default router; Il dato arriva in req.query.richiesta , viene incapsulato in uno HumanMessage e passato all'agente Generico senza altre modifiche: la rotta fa solo da ponte tra HTTP e l'agente. Esercizio Avvia il server e prova la rotta dal browser con una domanda diversa nella query string, ad esempio una che faccia scattare il tool get_weather dell'agente Generico. Mostra soluzione http://localhost:3000/ai?richiesta=Che tempo fa a Milano in gradi Fahrenheit

### Express: la rotta POST /ai/chat
Con express.json() attivo, una rotta POST può leggere i dati dal corpo ( body ) della richiesta invece che dalla query string: è il formato più comodo per un client che invia un messaggio di chat. Aggiungiamo alla stessa router una seconda rotta, questa volta POST, che riceve un JSON con il messaggio dell'utente e restituisce la risposta come JSON. routers/aiRouter.js — POST /ai/chat // http://localhost:3000/ai/chat // Corpo della richiesta: // { "message": "Ciao come stai" } router.post('/chat', async (req, res) => { const datiIngresso = req.body; const messaggioInIngresso = datiIngresso.message; const messageFull = ` Questa la richiesta che ti è stata fatta: ${messaggioInIngresso} Rispondi in maniera testuale, evita Markdown. ` const response = await genericAgent.invoke({ messages: [new HumanMessage(messageFull)] }); const responseText = response.messages.at(-1).content; res.json({ risposta: responseText }); }); Le due rotte inoltrano entrambe la domanda allo stesso agente Generico: cambia solo da dove arriva il dato (query string per GET, corpo JSON per POST) e come viene restituita la risposta (testo semplice per GET, oggetto JSON per POST). Esercizio Fai una chiamata POST a http://localhost:3000/ai/chat e prova a inviare nel corpo un dato, poi leggi la risposta JSON restituita. Mostra soluzione { "message": "Consigliami un prodotto per lo smart working" }

### Tool getProducts(): dalla lista completa ai dati alleggeriti
Il modello non ha bisogno di ricevere tutti i campi di ogni prodotto per rispondere: meno dati nel contesto significano risposte più veloci ed economiche. Una prima versione, la più semplice, restituisce l'intero array così com'è: async function getProductsFunction({}) { // Versione naive: passiamo TUTTI i campi di TUTTI i prodotti return JSON.stringify(products); } Funziona, ma è sprecato: se lo store ha centinaia di prodotti, ognuno con una lunga descrizione, il modello riceve nel contesto molti più dati di quanti gliene servano solo per capire quali prodotti esistono. Alleggeriamo la risposta con una map che tiene solo id e name : tools/getProducts.js import { tool } from 'langchain'; import products from '../data/db.js'; import { z } from 'zod'; const schema = z.object({}); async function getProductsFunction({}) { const productsLight = products.map(product => { return { id: product.id, name: product.name }; }); return JSON.stringify(productsLight); } const getProducts = tool(getProductsFunction, { name: "get_products", description: "Tool da utilizzare per ottenere informazioni sui prodotti dello store", schema }); export { getProducts }; Lo schema è un z.object({}) vuoto: questo tool non ha bisogno di nessun parametro in input, restituisce sempre l'intera lista alleggerita. Esercizio Modifica getProducts per includere anche il campo price nella versione alleggerita, insieme a id e name . Mostra soluzione const productsLight = products.map(product => { return { id: product.id, name: product.name, price: product.price }; });

### Tool getProductInfo(id): il dettaglio del prodotto
Quando l'agente ha già scelto quale prodotto interessa (tramite il suo id ), può chiedere il dettaglio completo: qui i dati alleggeriti non bastano più. A differenza di getProducts , questo tool richiede un parametro ( id ) e restituisce tutti i campi del singolo prodotto trovato, descrizione compresa. tools/getProductInfo.js import { tool } from 'langchain'; import products from '../data/db.js'; import { z } from 'zod'; const schema = z.object({ id: z.number().describe("l'ID del prodotto di cui vuoi informazioni") }); async function getProductinfoFunction({ id }) { const productFind = products.find((product) => { return product.id === id; }); if (productFind) { return JSON.stringify(productFind); } else { return 'Nessun prodotto trovato'; } } const getProductInfo = tool(getProductinfoFunction, { name: "get_product_info", description: "Tool da utilizzare per ottenere informazioni sul singolo prodotto dello store", schema }); export { getProductInfo }; Il flusso tipico è quindi in due passi: prima l'agente chiama get_products per vedere la lista leggera, poi chiama get_product_info con l' id del prodotto scelto per averne i dettagli completi. Esercizio Gestisci il caso in cui l'agente passa un id che non esiste nell'array, restituendo un messaggio d'errore chiaro che indichi anche l'id cercato. Mostra soluzione if (productFind) { return JSON.stringify(productFind); } else { return `Nessun prodotto trovato con id ${id}`; }

### Tool searchProduct(): la ricerca per nome
Quando l'utente non conosce l' id ma solo (parte del) nome del prodotto, serve un tool di ricerca: filtra per corrispondenza parziale, senza distinguere maiuscole e minuscole. Come getProducts , anche questo tool restituisce solo id e name dei prodotti trovati: l'agente userà poi get_product_info se avrà bisogno del dettaglio completo di uno di questi risultati. tools/searchProduct.js import { tool } from 'langchain'; import products from '../data/db.js'; import { z } from 'zod'; const schema = z.object({ nameSearch: z.string().describe("il nome del prodotto da cercare") }); async function searchProductFunction({ nameSearch }) { const productsFound = products .filter(product => { return product.name.toLocaleLowerCase().includes(nameSearch.toLocaleLowerCase()); }) .map(product => { return { id: product.id, name: product.name }; }); if (productsFound.length === 0) { return 'Nessun prodotto trovato'; } else { return JSON.stringify(productsFound); } } const searchProduct = tool(searchProductFunction, { name: "search_product", description: "Tool da utilizzare per cercare un prodotto nello store in base al nome", schema }); export { searchProduct }; toLocaleLowerCase() viene applicato su entrambi i lati del confronto, così la ricerca funziona indipendentemente da come l'utente scrive il nome (maiuscolo, minuscolo o misto). Esercizio Modifica searchProduct per restituire anche il campo price insieme a id e name nei risultati trovati. Mostra soluzione .map(product => { return { id: product.id, name: product.name, price: product.price }; });

### Collegare tutti i tool all'agente Generico
Con i quattro tool pronti, colleghiamoli tutti insieme all'agente Generico: sarà lui a decidere, di volta in volta, quale usare (o quanti, in sequenza) per rispondere. Nell'agente Generico visto nel capitolo sulla struttura delle cartelle mancava ancora getProducts . Aggiungiamolo: l'agente Generico avrà così tutti e quattro i tool a disposizione. agents/generic.js — versione completa import { createAgent } from "langchain"; import anthropicModel from '../models/anthropic.js'; import { getWeather } from '../tools/getWeather.js'; import { getProducts } from '../tools/getProducts.js'; import { getProductInfo } from '../tools/getProductInfo.js'; import { searchProduct } from '../tools/searchProduct.js'; const genericAgent = createAgent({ model: anthropicModel, tools: [ getWeather, getProducts, getProductInfo, searchProduct, ], }); export default genericAgent; Proviamo la rotta Fai una chiamata POST a http://localhost:3000/ai/chat e prova a inviare nel corpo il seguente dato: { "message": "Dimmi il prezzo di tutti i tuoi microfoni del tuo negozio" } Cosa succede dietro le quinte Nessuno dei quattro tool restituisce direttamente "tutti i microfoni con il prezzo": l'agente deve combinarli. Il ragionamento più probabile, passo dopo passo: get_products non basta: restituisce id e name di tutti i prodotti, ma non il prezzo. L'agente riconosce "microfoni" nella domanda e chiama search_product con nameSearch: "microfono" . Per rispondere con il prezzo di ciascun microfono, deve chiamare get_product_info(id) una volta per ogni risultato trovato.
