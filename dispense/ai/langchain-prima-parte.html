LangChain: modelli, storico della chat e primo agente

Imparare a usare LangChain con un modello Anthropic, capire perché un LLM è stateless, gestire manualmente lo storico di una chat e creare un primo agente con un tool meteo mock.

Capitolo 1

Creazione del progetto

Creiamo una cartella dedicata agli esempi della lezione.

# Creiamo una nuova cartella per il progetto.
mkdir langchain-prima-parte

# Entriamo nella cartella del progetto.
cd langchain-prima-parte

# Creiamo il file package.json iniziale.
pnpm init

Apriamo package.json e modifichiamolo in questo modo.

{
    "name": "langchain-prima-parte",
    "version": "1.0.0",
    "private": true,
    "type": "module",
    "scripts": {
        "dev": "node --watch index.js",
        "start": "node index.js"
    }
}

Capitolo 2

Installazione delle librerie

Installiamo le librerie che ci serviranno.

# Installiamo LangChain: contiene modelli, messaggi, tool e agenti.
pnpm add langchain

# Installiamo l'adapter che permette a LangChain di comunicare con Anthropic.
pnpm add @langchain/anthropic

# Installiamo Zod, utile per descrivere e validare gli input dei tool.
pnpm add zod

# Installiamo dotenv, che carica le variabili del file .env.
pnpm add dotenv

Ruolo delle librerie

Libreria A cosa serve
langchain Contiene i messaggi, i tool e gli agenti
@langchain/anthropic Permette di usare i modelli Anthropic tramite LangChain
zod Permette di definire e validare la struttura degli input di un tool
dotenv Carica le variabili del file .env in process.env

Capitolo 3

Configurazione della chiave API

Per comunicare con Anthropic serve una chiave API.

Creiamo un file chiamato .env nella cartella principale del progetto.

# Chiave API usata per autenticare le richieste verso Anthropic.
ANTHROPIC_API_KEY=la_tua_chiave_api_qui

Non inserire mai una chiave API direttamente nei file JavaScript.

Creiamo anche un file .env.example.

# Copiare questo file in .env e sostituire il valore con una chiave API reale.
ANTHROPIC_API_KEY=la_tua_chiave_api_qui

Infine, creiamo o aggiorniamo il file .gitignore.

# Il file .env contiene segreti e non deve essere caricato su GitHub.
.env

# Cartella creata automaticamente quando installiamo le dipendenze.
node_modules

Perché usare process.env?

Le variabili nel file .env vengono caricate dalla libreria dotenv. Basta importarla come prima riga di ogni file che eseguiamo:

// Carica le variabili del file .env in process.env.
import 'dotenv/config';

La chiave sarà disponibile nel programma tramite process.env.ANTHROPIC_API_KEY.

In questo caso non dobbiamo leggerla manualmente: l'adapter ChatAnthropic la utilizza automaticamente quando è presente nell'ambiente.

Capitolo 4

Hello World con LangChain

Un chat model riceve messaggi e genera messaggi di risposta.

Con LangChain useremo ChatAnthropic per creare un modello collegato ad Anthropic.

Crea il file index.js.

// Carica la chiave API dal file .env.
import 'dotenv/config';

// ChatAnthropic è l'adapter LangChain che permette di usare i modelli Anthropic.
import { ChatAnthropic } from '@langchain/anthropic';

// HumanMessage rappresenta un messaggio scritto dall'utente.
import { HumanMessage } from 'langchain';

// Creiamo il modello indicando solo il modello Anthropic da utilizzare.
const model = new ChatAnthropic({
    model: 'claude-haiku-4-5-20251001'
});

try {
    // Anche se abbiamo un solo messaggio, usiamo sempre un array di HumanMessage.
    const messages = [
        new HumanMessage('Ciao! Spiegami in una frase che cos’è LangChain.')
    ];

    // invoke() invia l'array di messaggi al modello e attende la risposta.
    const response = await model.invoke(messages);

    // response è un AIMessage. La proprietà content contiene il testo generato.
    console.log('RISPOSTA DEL MODELLO:');
    console.log(response.content);
} catch (error) {
    // Mostriamo un messaggio utile in caso di errore di configurazione o rete.
    console.error('Impossibile contattare Anthropic. Controlla la chiave API e la connessione.', error);
}

Avviamo il programma.

# Avvia il programma e lo riavvia automaticamente quando salviamo modifiche.
pnpm run dev

Cosa fa model.invoke()?

model.invoke():

  1. riceve un array di messaggi;
  2. invia i messaggi al modello;
  3. attende la risposta;
  4. restituisce un oggetto AIMessage.

Nell'esempio precedente il modello riceve un array con un solo elemento:

// L'array rappresenta lo storico della conversazione.
const messages = [
    new HumanMessage('Ciao! Spiegami in una frase che cos’è LangChain.')
];

Capitolo 5

LLM stateless e storico dei messaggi

Un LLM è stateless.

Questo significa che una chiamata a model.invoke() non conserva automaticamente ciò che è accaduto nella chiamata precedente.

Esempio concettuale

Immaginiamo queste due chiamate separate:

Prima chiamata:
Utente: "Ciao, mi chiamo Samuel."

Seconda chiamata:
Utente: "Qual è la genesi del mio nome?"

Se nella seconda chiamata non inviamo anche il primo messaggio, il modello non riceve l'informazione che il nome dell'utente è Samuel.

Esempio stateless

Crea il file 01-stateless.js.

// Carica la chiave API dal file .env.
import 'dotenv/config';

// ChatAnthropic permette di usare Claude tramite LangChain.
import { ChatAnthropic } from '@langchain/anthropic';

// HumanMessage rappresenta ogni messaggio scritto dall'utente.
import { HumanMessage } from 'langchain';

// Creiamo il modello indicando il modello Anthropic da usare.
const model = new ChatAnthropic({
    model: 'claude-haiku-4-5-20251001'
});

try {
    // Prima chiamata: il modello riceve un array con un solo messaggio.
    const firstResponse = await model.invoke([
        new HumanMessage('Ciao, mi chiamo Samuel.')
    ]);

    console.log('PRIMA RISPOSTA:');
    console.log(firstResponse.content);

    // Seconda chiamata: creiamo un nuovo array con un nuovo messaggio.
    // Il modello non riceve il messaggio precedente.
    const secondResponse = await model.invoke([
        new HumanMessage('Qual è la genesi del mio nome?')
    ]);

    console.log('\nSECONDA RISPOSTA:');
    console.log(secondResponse.content);
} catch (error) {
    // Gestiamo eventuali problemi di configurazione, rete o autenticazione.
    console.error('Errore durante la conversazione:', error);
}

Eseguiamo il file.

# dotenv è importato nel file: non servono flag aggiuntivi.
node 01-stateless.js

Cosa osservare

Le due invocazioni sono indipendenti.

Nella seconda chiamata il modello riceve solamente:

Qual è la genesi del mio nome?

Non riceve il messaggio:

Ciao, mi chiamo Samuel.

Il modello potrebbe comunque conoscere il significato del nome Samuel, ma non perché lo ha memorizzato durante la prima chiamata. Lo sa perché il nome è presente nella sua conoscenza generale.

Per vedere più chiaramente il problema, possiamo usare una parola inventata.

// Carica la chiave API dal file .env.
import 'dotenv/config';

// Questo esempio usa una parola inventata per rendere evidente
// che il modello non conserva automaticamente memoria tra due chiamate.
import { ChatAnthropic } from '@langchain/anthropic';
import { HumanMessage } from 'langchain';

const model = new ChatAnthropic({
    model: 'claude-haiku-4-5-20251001'
});

try {
    // Il modello riceve la parola segreta soltanto in questa chiamata.
    await model.invoke([
        new HumanMessage('Ricorda che la parola segreta di oggi è marmotta-blu.')
    ]);

    // Questa è una nuova richiesta indipendente.
    // La parola marmotta-blu non viene reinviata.
    const response = await model.invoke([
        new HumanMessage('Qual è la parola segreta di oggi?')
    ]);

    console.log(response.content);
} catch (error) {
    console.error('Errore durante l’esempio stateless:', error);
}

Capitolo 6

Gestire lo storico della chat

Per permettere al modello di conoscere i messaggi precedenti, dobbiamo conservare manualmente lo storico della conversazione.

Lo storico sarà un array chiamato messages.

L'array conterrà:

  • i messaggi dell'utente, rappresentati da HumanMessage;
  • le risposte del modello, rappresentate da AIMessage.

Non dobbiamo creare manualmente l'AIMessage: lo riceviamo come risultato di model.invoke().

Esempio con storico

Crea il file 02-storico-chat.js.

// Carica la chiave API dal file .env.
import 'dotenv/config';

// ChatAnthropic permette di usare Claude tramite LangChain.
import { ChatAnthropic } from '@langchain/anthropic';

// HumanMessage rappresenta un messaggio dell'utente.
import { HumanMessage } from 'langchain';

// Creiamo il modello Anthropic.
const model = new ChatAnthropic({
    model: 'claude-haiku-4-5-20251001'
});

// Questo array contiene l'intero storico della conversazione.
const messages = [];

try {
    // Aggiungiamo il primo messaggio dell'utente allo storico.
    messages.push(
        new HumanMessage('Ciao, mi chiamo Samuel.')
    );

    // Inviamo tutto lo storico al modello.
    const firstResponse = await model.invoke(messages);

    // Salviamo nello storico anche la risposta del modello.
    // In questo modo il prossimo turno conoscerà sia domanda sia risposta.
    messages.push(firstResponse);

    console.log('ASSISTENTE:');
    console.log(firstResponse.content);

    // Aggiungiamo il secondo messaggio dell'utente allo stesso array.
    messages.push(
        new HumanMessage('Qual è la genesi del mio nome?')
    );

    // Inviamo nuovamente l'intero storico, non solo l'ultima domanda.
    const secondResponse = await model.invoke(messages);

    // Salviamo anche la seconda risposta nel caso la chat continui.
    messages.push(secondResponse);

    console.log('\nASSISTENTE:');
    console.log(secondResponse.content);

    // Mostriamo quanti messaggi sono stati salvati nello storico.
    console.log(`\nMessaggi nello storico: ${messages.length}`);
} catch (error) {
    // Gestiamo eventuali errori durante la chiamata al modello.
    console.error('Errore durante la gestione dello storico:', error);
}

Eseguiamo il file.

# dotenv è importato nel file: non servono flag aggiuntivi.
node 02-storico-chat.js

Come cambia lo storico?

Dopo il primo messaggio dell'utente:

1. HumanMessage: "Ciao, mi chiamo Samuel."

Dopo la risposta del modello:

1. HumanMessage: "Ciao, mi chiamo Samuel."
2. AIMessage: "Ciao Samuel, piacere di conoscerti..."

Dopo il secondo messaggio dell'utente:

1. HumanMessage: "Ciao, mi chiamo Samuel."
2. AIMessage: "Ciao Samuel, piacere di conoscerti..."
3. HumanMessage: "Qual è la genesi del mio nome?"

A questo punto il modello può collegare l'espressione “il mio nome” al nome Samuel, perché riceve anche il primo messaggio.

Attenzione: lo storico cresce

A ogni nuovo turno aggiungiamo messaggi nell'array.

Questo comporta due conseguenze:

  • aumentano i token inviati al modello;
  • una conversazione molto lunga può superare il limite di contesto del modello.

Per ora gestiamo manualmente lo storico, perché è il modo più semplice per capire come funziona. In futuro potremo selezionare solo i messaggi più importanti oppure creare un riassunto della conversazione.

Capitolo 7

Il limite dei dati aggiornati

Un LLM è molto bravo a generare testo, spiegare concetti, riformulare contenuti e ragionare sui dati che riceve.

Tuttavia non può conoscere automaticamente informazioni aggiornate in tempo reale.

Per esempio, proviamo a chiedere:

Che tempo fa a Pisa?

Crea il file 03-senza-tool.js.

// Carica la chiave API dal file .env.
import 'dotenv/config';

// ChatAnthropic permette di inviare messaggi a un modello Anthropic.
import { ChatAnthropic } from '@langchain/anthropic';

// HumanMessage rappresenta il messaggio scritto dall'utente.
import { HumanMessage } from 'langchain';

// Creiamo il modello Anthropic.
const model = new ChatAnthropic({
    model: 'claude-haiku-4-5-20251001'
});

try {
    // Il modello riceve soltanto la domanda dell'utente.
    // Non riceve dati meteorologici in tempo reale.
    const response = await model.invoke([
        new HumanMessage('Che tempo fa a Pisa in questo momento?')
    ]);

    console.log(response.content);
} catch (error) {
    console.error('Errore durante la richiesta meteo:', error);
}

Il modello potrebbe rispondere che non possiede dati in tempo reale oppure potrebbe fornire informazioni generiche sul clima di Pisa.

Per ottenere dati aggiornati dobbiamo dare al modello uno strumento che possa recuperare informazioni dall'esterno.

Questo strumento viene chiamato tool.

Capitolo 8

Tool e Zod

Un tool è una funzione JavaScript che un agente può decidere di usare.

Un tool è composto da quattro parti principali:

  1. una funzione JavaScript che contiene la logica;
  2. un nome tecnico;
  3. una descrizione per il modello;
  4. uno schema che descrive gli argomenti richiesti.

Esempio concettuale

Un tool meteo potrebbe ricevere una città:

get_weather({ city: "Pisa" })

Il modello non esegue direttamente il codice JavaScript. Il modello decide di richiamare il tool indicando gli argomenti; LangChain esegue la funzione; infine il risultato viene reinviato al modello.

Che cos'è Zod?

Zod è una libreria per descrivere e validare dati JavaScript.

Nel nostro caso useremo Zod per dire che il tool meteo richiede un oggetto con una proprietà city di tipo stringa.

// z.object() descrive un oggetto.
// La proprietà city deve contenere una stringa.
const getWeatherSchema = z.object({
    city: z.string()
});

Se il modello costruisse una chiamata non valida, lo schema aiuta LangChain a rilevare il problema.

Capitolo 9

Creare il tool meteo mock

In questa prima lezione non useremo una vera API meteorologica.

Creeremo invece un mock: una funzione che simula un servizio meteo e restituisce sempre lo stesso risultato.

Questo ci permette di concentrarci sul funzionamento di tool e agenti senza introdurre API key aggiuntive, richieste HTTP o gestione di dati esterni.

Struttura delle cartelle

Creiamo una cartella chiamata tools.

langchain-prima-parte/
├── tools/
│   └── getWeather.js
├── .env
├── .env.example
├── .gitignore
├── index.js
├── 01-stateless.js
├── 02-storico-chat.js
├── 03-senza-tool.js
├── 04-agente-meteo.js
└── package.json

Tool get_weather

Crea il file tools/getWeather.js.

// tool() trasforma una funzione JavaScript in un tool utilizzabile da LangChain.
import { tool } from 'langchain';

// Zod permette di descrivere e validare gli argomenti del tool.
import { z } from 'zod';

/**
 * Questa funzione contiene la logica del tool meteo.
 *
 * Per questa prima lezione è un mock: non chiama servizi esterni
 * e restituisce sempre lo stesso risultato, indipendentemente dalla città.
 *
 * @param {{ city: string }} parameters - Oggetto ricevuto dal tool.
 * @returns {Promise<string>} Una frase con il meteo simulato.
 */
async function getWeatherFunction({ city }) {
    // Usiamo city solo per evitare un parametro inutilizzato.
    // Nella versione mock non cambia il risultato restituito.
    void city;

    // Il tool restituisce sempre una stringa, non un oggetto JSON.
    return 'Il meteo è sereno con una temperatura di 22 °C. Dati forniti da un mock didattico.';
}

// Lo schema è separato dalla funzione del tool.
// Specifica che il tool richiede un oggetto con una proprietà city di tipo stringa.
const getWeatherSchema = z.object({
    city: z.string().describe('La città di cui si vuole conoscere il meteo.')
});

// Creiamo il tool collegando la funzione alla sua configurazione.
const getWeather = tool(getWeatherFunction, {
    // Nome tecnico che il modello utilizza per richiamare il tool.
    name: 'get_weather',

    // Descrizione usata dal modello per capire quando usare il tool.
    description: 'Restituisce il meteo attuale di una città italiana.',

    // Schema Zod definito separatamente.
    schema: getWeatherSchema
});

// Esportiamo il tool per poterlo importare nel file dell'agente.
export default getWeather;

Parti del tool

Parte Ruolo
getWeatherFunction Contiene la logica eseguita quando il tool viene chiamato
getWeatherSchema Definisce gli argomenti che il tool si aspetta
name È il nome tecnico usato dal modello per richiamare il tool
description Spiega al modello quando è opportuno usare il tool
tool(...) Collega funzione, schema e metadati creando il tool LangChain

Perché il mock restituisce sempre una stringa?

Il nostro obiettivo non è ancora costruire un servizio meteo realistico.

Vogliamo solo dimostrare che:

  1. l'utente fa una domanda;
  2. l'agente riconosce che serve il tool;
  3. LangChain esegue getWeatherFunction();
  4. la funzione restituisce una stringa;
  5. il modello usa quella stringa per creare una risposta finale.

Capitolo 10

Creare un agente LangChain

Un agente collega un modello a uno o più tool.

A differenza di una chiamata diretta a model.invoke(), l'agente può decidere se un tool è necessario per rispondere alla richiesta dell'utente.

Crea il file 04-agente-meteo.js.

// Carica la chiave API dal file .env.
import 'dotenv/config';

// ChatAnthropic permette di usare Claude tramite LangChain.
import { ChatAnthropic } from '@langchain/anthropic';

// createAgent crea un agente che può utilizzare uno o più tool.
// HumanMessage rappresenta il messaggio inviato dall'utente.
import { createAgent, HumanMessage } from 'langchain';

// Importiamo il tool meteo creato nella cartella tools.
import getWeather from './tools/getWeather.js';

// Creiamo il modello indicando soltanto il modello Anthropic scelto.
const model = new ChatAnthropic({
    model: 'claude-haiku-4-5-20251001'
});

// Creiamo un agente e gli rendiamo disponibile il tool get_weather.
const agent = createAgent({
    model,
    tools: [getWeather],

    // Il system prompt contiene istruzioni permanenti per l'agente.
    systemPrompt: `
Sei un assistente meteorologico didattico.
Quando l'utente chiede il meteo di una città, usa il tool get_weather.
Dichiara sempre che i dati restituiti provengono da un mock didattico.
`
});

try {
    // Anche agent.invoke() riceve sempre un array di HumanMessage.
    // Non usiamo l'oggetto abbreviato con role e content.
    const result = await agent.invoke({
        messages: [
            new HumanMessage('Che tempo fa a Pisa?')
        ]
    });

    // L'ultimo messaggio prodotto dall'agente è la risposta finale.
    const finalMessage = result.messages.at(-1);

    console.log('RISPOSTA FINALE DELL’AGENTE:');
    console.log(finalMessage.content);
} catch (error) {
    // Gestiamo possibili problemi di configurazione, rete o autenticazione.
    console.error('Errore durante l’esecuzione dell’agente:', error);
}

Eseguiamo il file.

# dotenv è importato nel file: non servono flag aggiuntivi.
node 04-agente-meteo.js

Cosa accade durante l'esecuzione?

  1. L'utente invia la domanda: “Che tempo fa a Pisa?”
  2. L'agente riceve un array con un HumanMessage.
  3. Il modello legge la domanda, le istruzioni e la descrizione del tool.
  4. Il modello decide di chiamare get_weather.
  5. LangChain esegue getWeatherFunction().
  6. La funzione restituisce la stringa del mock.
  7. Il risultato del tool viene passato al modello.
  8. Il modello produce una risposta finale per l'utente.

Rappresentazione del flusso

Visualizzare tutti i messaggi dell'agente

Per capire meglio cosa avviene, possiamo stampare tutti i messaggi prodotti dall'agente.

// Dopo agent.invoke(), result.messages contiene lo storico completo
// prodotto durante il lavoro dell'agente.
console.log(result.messages);

Nell'array potremmo trovare:

  • il messaggio iniziale dell'utente;
  • un messaggio del modello che richiede il tool;
  • un messaggio con il risultato del tool;
  • il messaggio finale del modello.

Capitolo 11

Esercizi sui tool

Gli esercizi seguenti permettono di praticare la creazione di tool senza usare API reali.

Per ogni esercizio:

  1. creare una funzione separata;
  2. creare uno schema Zod separato;
  3. creare il tool con tool();
  4. collegare il tool a un agente;
  5. fare domande all'agente per verificare che scelga il tool giusto.

Esercizio 1 — Informazioni su Pokémon

Creare un tool chiamato get_pokemon_info.

Lo schema potrebbe essere:

// Lo schema richiede il nome del Pokémon da cercare.
const getPokemonInfoSchema = z.object({
    name: z.string().min(1).describe('Il nome del Pokémon da cercare.')
});

La funzione mock può restituire sempre questa stringa:

// La funzione restituisce sempre un testo mock per il primo esercizio.
async function getPokemonInfoFunction({ name }) {
    void name;

    return 'Pikachu è un Pokémon di tipo Elettro introdotto nella regione di Kanto.';
}

Esempi di domande:

  • “Che tipo è Pikachu?”
  • “Dammi informazioni su Charmander.”
  • “In quale regione è stato introdotto Pikachu?”

Esercizio 2 — Materiale del corso

Creare un tool chiamato search_course_material.

Lo schema potrebbe essere:

// Lo schema richiede una parola chiave da cercare nel materiale del corso.
const searchCourseMaterialSchema = z.object({
    query: z.string().min(2).describe('La parola chiave da cercare nel materiale del corso.')
});

La funzione mock può restituire:

// La funzione simula una ricerca in una raccolta di dispense.
async function searchCourseMaterialFunction({ query }) {
    void query;

    return 'Ho trovato una dispensa su Express che tratta routing, middleware e controller.';
}

Esempi di domande:

  • “Abbiamo materiale sui middleware?”
  • “Cerca una lezione su Express.”
  • “Dove abbiamo parlato di controller?”

Esercizio 3 — Informazioni su giochi da tavolo

Creare un tool chiamato get_board_game_info.

Lo schema potrebbe essere:

// Lo schema richiede il titolo del gioco da tavolo.
const getBoardGameInfoSchema = z.object({
    title: z.string().min(2).describe('Il titolo del gioco da tavolo.')
});

La funzione mock può restituire:

// La funzione restituisce una descrizione fittizia del gioco richiesto.
async function getBoardGameInfoFunction({ title }) {
    void title;

    return 'Wingspan è un gioco da tavolo per 1-5 giocatori, con una durata media di circa 70 minuti.';
}

Esempi di domande:

  • “Quanti giocatori supporta Wingspan?”
  • “Quanto dura una partita a Wingspan?”

Esercizio 4 — Calcolo preventivo

Creare un tool chiamato calculate_quote.

In questo esercizio la funzione può usare davvero i dati ricevuti.

// Lo schema richiede ore di lavoro e tariffa oraria.
const calculateQuoteSchema = z.object({
    hours: z.number().positive().describe('Numero di ore di lavoro.'),
    hourlyRate: z.number().positive().describe('Tariffa oraria in euro.')
});
// La funzione calcola un preventivo e restituisce una stringa leggibile.
async function calculateQuoteFunction({ hours, hourlyRate }) {
    const total = hours * hourlyRate;

    return `Il preventivo per ${hours} ore a ${hourlyRate} euro l'ora è di ${total} euro.`;
}

Esempi di domande:

  • “Calcola un preventivo per 8 ore a 35 euro l'ora.”
  • “Quanto costa un lavoro di 12 ore a 50 euro l'ora?”

Esercizio 5 — Pacchetti fotografici

Creare un tool chiamato get_photo_session_package.

Lo schema potrebbe essere:

// Lo schema limita il tipo di servizio a tre valori ammessi.
const getPhotoSessionPackageSchema = z.object({
    type: z.enum(['ritratto', 'evento', 'prodotto'])
        .describe('Il tipo di servizio fotografico richiesto.')
});

La funzione mock può restituire:

// La funzione restituisce una proposta di pacchetto fotografico fittizio.
async function getPhotoSessionPackageFunction({ type }) {
    void type;

    return 'Il pacchetto ritratto include un’ora di scatti e dieci fotografie post-prodotte.';
}

Capitolo 12

Riepilogo

In questa prima parte abbiamo visto che:

  1. LangChain aiuta a lavorare con LLM, messaggi, tool e agenti.
  2. ChatAnthropic è il componente usato per comunicare con Anthropic.
  3. Il modello viene creato indicando la proprietà model.
  4. Ogni chiamata a model.invoke() riceve sempre un array di HumanMessage.
  5. Un LLM è stateless: non conserva automaticamente le chiamate precedenti.
  6. Per creare una conversazione dobbiamo mantenere un array chiamato messages.
  7. Dopo ogni chiamata dobbiamo aggiungere allo storico anche la risposta del modello.
  8. Un LLM non possiede automaticamente dati aggiornati, come il meteo in tempo reale.
  9. Un tool è una funzione che un agente può scegliere di usare.
  10. Zod descrive e valida gli argomenti che il tool riceve.
  11. Un agente collega il modello ai tool disponibili.
  12. Anche agent.invoke() riceve messaggi rappresentati con HumanMessage.
  13. Il nostro tool meteo mock ha funzione e schema separati e restituisce sempre una stringa.
